- На главной доступны «Курс по модулям» и «Тренировка по темам». Прежние шесть рубрик находятся во втором разделе.

- Все подготовленные модули доступны без обязательного последовательного открытия.
- Модуль открывает список постоянных уроков, урок запускает карточки. Отображать номер урока, количество записей и исходные разделы учебника.
- Состав уроков фиксируется в данных. Сохранять последовательность исходника и принадлежность к разделу; урок при необходимости может включать соседние разделы. Границы разделов не терять. Не заявлять, что занятия точно соответствуют разделам учебника.
- Для N записей создать ceil(N / 10) уроков, распределить записи максимально равномерно; более длинные уроки идут первыми. Получаются размеры из таблицы. Случайно перемешивается прохождение, а не состав уроков.
- Все записи модуля входят в уроки ровно по одному разу по идентификатору исходной строки. Повтор одинакового написания в другом контексте сохраняется.
- При поэтапной разработке неподготовленные модули видны с подписью «Готовится» и не запускают неполные задания. Кнопки без работающего содержимого не создавать.

### 3. Подготовка данных

- Excel преобразуется заранее при разработке; приложение не разбирает XLSX и не загружает его в интернет. Кнопка импорта пользователем в эту функцию не входит.
- Рабочий словарь хранится в script.js, как в текущем проекте. Дополнительные runtime-файлы и библиотеки для чтения Excel не вводить.
- Для каждой записи хранить стабильный идентификатор на основе номера строки/№ источника, модуль, раздел, оригинальное английское написание, часть речи, три языковых варианта, IPA и исходное примечание.
- Сохранять исходные значения отдельно от отредактированных учебных переводов, чтобы исправления оставались проверяемыми. В интерфейсе задания показывать один подходящий перевод; дополнительные значения использовать в справке по контексту, а не как длинный перечень ответов.
- Примечания просмотреть до подготовки учебной версии: среди них есть исправления части речи, опечаток и значений. Не выдавать исходные неточности за проверенный учебный контент.
- Дополнить 67 отсутствующих IPA после проверки произношения. Не генерировать транскрипцию механической заменой букв. Если произношение ещё не проверено, явно отметить запись как неподготовленную; модуль с неполным контентом не объявлять готовым.
- Подготовить короткие примеры на трёх языках для карточек, предложения второго уровня и подсказки по спецификации 004 для всех реально используемых английских предложений.
- Сочетания вроде bedside cabinet и proud of изучать целиком. Пропуск второго уровня может заменять всё сочетание; один ответ может состоять из нескольких слов.
- Не объединять записи только по одинаковому English. Для одинакового написания с разным значением нужен явный контекст в карточке. Если контекст всё ещё допускает два ответа, исправить задание до включения в урок.
- Неправильные варианты карточек брать прежде всего из урока, при необходимости из модуля. Исключать одинаковые отображаемые ответы, синонимы правильного значения и неоднозначность; всегда три разных варианта и один правильный ответ.
- На уровне предложений неверные варианты подбирать по смыслу и грамматике отдельно, а не случайно из всего словаря.

### 4. Обучение и итоги

- Сохранить механику первого уровня: одна карточка, случайный исходный язык с равными вероятностями, два перевода в случайном порядке, обязательное правильное завершение обоих этапов. Внутри попытки записи не повторяются.
- Для n записей количество переводов равно 2n. В интерфейсе и расчётах использовать реальное количество, не константу 20.
- `firstTry` — число отдельных переводов, правильно завершённых без единой ошибки. Два перевода одной записи учитываются независимо; переворот и повтор сами по себе счётчики не меняют.
- Предложения открываются после полного первого уровня, если firstTry >= ceil(0.8 * 2n). В сообщении указывать фактический порог и знаменатель.
- На втором уровне n предложений, каждое целевое понятие урока используется один раз. Для 10 записей состав 4 английских / 4 казахских / 2 русских; для 9 — 4 английских / 4 казахских / 1 русское. Оба состава обеспечивают приоритет английского и казахского и гарантируются в каждом прохождении, включая повтор. Порядок случайный.
- Сложность предложений, грамматические формы, единственность ответа, обработка ошибок и подсказки сохраняются по спецификациям 003 и 004.
- Итоги каждого уровня показывают реальное число заданий, верных с первой попытки, и число всех ошибочных выборов. Ошибка при повторной попытке увеличивает только число ошибок.
- «Повторить предложения» в текущем сеансе начинает только второй уровень заново и сохраняет уже полученный доступ, как в 003. Возврат из урока, выбор другого урока, новый запуск карточек и F5 сбрасывают этот доступ.
- Повтор урока начинает новую попытку с нулевыми счётчиками. История лучших завершённых результатов не обнуляется.

### 5. Прогресс и восстановление

- Для каждого урока показать «Не начат», «Карточки пройдены» или «Предложения пройдены», а также лучший завершённый результат каждого уровня. Не считать урок целиком пройденным после одних карточек.
- Статус «Карточки пройдены» означает, что первый уровень завершён, даже если порог доступа не достигнут. Дополнительно явно показывать, достигнут ли порог. «Предложения пройдены» — завершён второй уровень.
- Лучший результат выбирается отдельно для каждого уровня: больше верных с первой попытки, при равенстве — меньше ошибочных выборов. Сохранять пару показателей одной завершённой попытки, не собирать её из разных попыток. При полном равенстве оставить прежний результат. Завершение карточек ниже 80% также сохраняется, но не открывает предложения.
- Для курса это явное уточнение запрета сохранения результатов из 002–004; прежние тематические тренировки продолжают хранить результаты только в памяти.
- В localStorage сохранять выбранный раздел/модуль/урок и лучшие завершённые результаты. Это осознанное расширение прежнего сохранения только рубрики.
- Текущие ответы, очередность заданий и временный доступ к предложениям не сохранять. После F5 выбранный урок начинается с карточек заново, а его накопленные результаты остаются.
- Доступ к предложениям определяется текущей попыткой, а не прежним лучшим результатом. После F5 или нового запуска порог необходимо выполнить снова.
- Результаты разных исходных записей, уроков и модулей не смешивать. Структура сохранения имеет версию; идентификаторы стабильны при исправлении текста. При изменении состава урока старый результат нельзя приписывать новому составу.
- Существующий ключ slovarium.category и поведение старых тематических наборов сохраняются. Сохранённый выбор нового курса имеет приоритет восстановления только если пользователь последним выбрал курс.
- Неизвестные идентификаторы, повреждённый JSON, недоступное хранилище и ошибки записи не мешают занятиям; неверные данные игнорируются, несвязанные ключи не удаляются.
- Отдельное занятие «Повторение ошибок» не входит в эту функцию: его можно описать следующей спецификацией.

## Ограничения

- HTML/CSS/JavaScript без npm, библиотек, внешних ресурсов и сетевой передачи словаря; index.html работает двойным щелчком без сервера. XLSX не читать через fetch в браузере.
- Использовать UTF-8; казахские буквы и IPA не искажать. Системные шрифты, интерфейс на русском, кнопки и поля не меньше 44 × 44 CSS px, поддержка 375px.
- Не удалять действующие шесть тематических наборов. Запрет повторов понятий между ними из 001 сохраняется для старого набора; импорт курса сохраняет исходные повторные записи по правилам этой спецификации.
- Не утверждать, что все 829 записей являются разными понятиями или полностью проверены носителями языка. Источники IPA и статус языковой проверки фиксировать при подготовке контента.
- Не добавлять постоянное открытие второго уровня, аккаунты, облачную синхронизацию или импорт пользователем без отдельного запроса.
- AGENTS.md не переписывать автоматически. Правило 4/4/2 уже относится к 10 заданиям; состав 4/4/1 применяется только к новым урокам из 9 записей и не меняет старые наборы.
- После реализации обновить README: готовые модули, функции, запуск и проверка. Пользовательские разделы отчёта об обучении не выдумывать.
- git add и git commit выполняет пользователь.
